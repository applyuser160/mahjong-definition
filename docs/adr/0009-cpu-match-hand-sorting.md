# 0009: コンピュータ対局（CPU対局）における手牌の理牌（ソート）ポリシー

> **ADR番号:** 0009  
> **作成日:** 2026-09-14  
> **更新日:** 2026-09-14  
> **作成者:** Syun & AI Assistant

---

## ステータス

`Accepted`

---

## コンテキスト（Context）

ADR-0008 により `Hand::sort()` が導入され、何切るドリル（`DrillEngine`）において手牌の自動昇順整列（理牌）が実現された。  
しかし、4人コンピュータ対局（CLI `play_with_cpu.rs`、Web UI `match_manager.py`、コア `round.rs`）においては、依然として配牌時や打牌後に手牌がソートされておらず、手牌が乱雑に並び視認性と操作性が損なわれていた。  
また、Web UI の `match_manager.py` においては、`_sort_hand()` メソッド内で実際のリストソート処理（`self.hands[player_idx].sort(key=...)`）が欠落しており、プレイヤー手牌すらソートされていない不具合が存在した。  
実戦麻雀においては、「純手牌（13枚）は理牌され、ツモ牌（14枚目）は手牌の右端に独立配置される」「打牌した直後に残った13枚が再理牌される」という挙動が最も自然で認知負荷が低い。この理牌ライフサイクルを対局システム全体に導入する必要がある。

---

## 意思決定の要因（Decision Drivers）

- **視認性と認知負荷の低減**: 牌種（萬子・筒子・索子・字牌）順の整列により、シャンテン数や面子構成を瞬時に把握可能にする。
- **ツモ牌分離表示（`isLastDrawn`）との整合**: ツモ時に全14枚をソートしてしまうと、新しくツモった牌が手牌の途中に混ざってしまい、「何をツモってきたのか」が判別できなくなるため、ツモ時は純手牌のみが整列され、ツモ牌が末尾（右端）に配置される仕様を厳守する。
- **CLI / Web UI の一貫性**: ターミナル対局でもブラウザ対局でも同一の理牌体験を提供する。
- **パフォーマンスと低オーバーヘッド**: 手牌枚数は最大14枚であり、極めて軽量にインプレースソートを行う。

---

## 検討した選択肢（Considered Options）

- **選択肢 A (推奨)**: 「純手牌13枚を整列＋ツモ牌を末尾配置」し、「打牌直後に残手牌13枚を再整列」する方式を CLI (`play_with_cpu.rs`)、Web UI (`match_manager.py`)、コア (`round.rs`) で統一適用。
- **選択肢 B**: 描画（表示）時のみソートを行い、内部状態の `hands` はツモ順・手出し順のまま保持する。
- **選択肢 C**: ツモ時も含めて常に全14枚を完全ソートし、ツモ牌の区別を行わない。

---

## 決定結果（Decision Outcome）

**選択した選択肢:** 選択肢 A を選択。

**理由:**  
麻雀ゲームおよび実戦における標準的な理牌体験は「ツモ番中はツモ牌が右端にあり、打牌時に手牌に入って理牌される」形である。選択肢 C ではツモ牌がどこに入ったか追えなくなり、選択肢 B では描画層ごとにソート処理が重複しバグの温床となる。選択肢 A により、内部状態としても配牌時および打牌後に整列されるため、AIの打牌評価やCLI/Web双方での表示が自然かつ強固に整合する。

### 期待される効果（Positive Consequences）

- CLI対局およびWeb UI対局の両方で、配牌時・手番時・終局時の手牌が常に美しく理牌される。
- Web UIにおける `isLastDrawn` によるツモ牌の分離表示が崩れず、完全に機能する。
- `match_manager.py` 内の未実装だった `_sort_hand` バグが解消される。
- CPUの手牌も同様に整列されるため、流局時や終局時の手牌開帳でテンパイ形が明瞭に確認できる。

### 想定されるリスク（Negative Consequences）

- 特になし（ソート対象は最大14枚のスライス/リストであり、計算量は無視できるレベル）。

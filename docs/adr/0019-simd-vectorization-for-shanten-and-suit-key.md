# ADR 0019: AVX2/SIMD を活用した七対子判定・牌カウント内積のベクトル化

## 状態
承認 (Accepted)

## コンテキスト
麻雀の手牌カウント配列（`counts: [u8; 35]`）は、各牌の所持枚数を 1 バイト値としてインデックス 1〜34 に保持している。
これは x86_64 の 256bit AVX2 レジスタ（32 バイト）と極めて整合性の高いデータ構造である。
何切る解析やモンテカルロ木探索等において、七対子シャンテン数計算（`calculate_chitoitsu_shanten`）は数千万回呼ばれる最頻出関数の一つである。
従来のスカラー実装では、34 要素を逐次走査して条件分岐を伴う集計を行っており、ループオーバーヘッドと分岐ペナルティが存在していた。

しかしながら、Issue #109 において以下の 2 つの技術的留意点が指摘された：
1. `[u8; 35]` のアライメントは 1 であり、先頭 32 バイト整列が保証されないため、アライメント前提の `_mm256_load_si256` は未定義動作を起こす（未整列ロード `_mm256_loadu_si256` を用いる必要がある）。また対象は 34 要素であるため末尾 2 要素の処理が必要。
2. Base-5 の重み $5^7, 5^8$ は符号付き 16bit 整数（最大 32,767）の表現可能範囲を超えるため、単純な `_mm256_madd_epi16` 単一適用ではオーバーフローを起こす。

## 決定
1. **七対子の AVX2 ベクトル化**:
   - `_mm256_loadu_si256` を用いて 32 要素（インデックス 1〜32）を一括ロード。
   - `_mm256_cmpgt_epi8` による並列判定、`_mm256_movemask_epi8` と `count_ones()`（POPCNT）によるブランチレス集計を実装。
   - 末尾 2 要素（33: 発、34: 中）はスカラーで処理して合算。
2. **スーツキーの SIMD / スカラー最適化**:
   - Base-5 のオーバーフロー制約を考慮し、桁分割による積和、およびコンパイラ最適化とのベンチマーク比較を行い、最適な実装を採用する。
3. **マルチターゲット・フォールバックの担保**:
   - `is_x86_feature_detected!("avx2")` および `target_feature = "avx2"` による条件付きディスパッチを行い、非 AVX2 環境や ARM 環境での完全な動作互換性を維持する。
4. **差分テストの網羅性**:
   - ランダムな合法手牌、数牌の全有効パターン、特殊形の境界ケースに対してスカラー実装と AVX2 実装の出力が完全一致することを単体テスト・プロパティテストで検証する。

## 結果・影響
- 七対子判定のループおよび分岐が完全に排除され、POPCNT を含むハードウェア命令で数サイクルで計算が完了する。
- 既存の全テスト・プロパティテストとの完全な同値性を維持しながら、シャンテン数計算ホットパスの高速化が達成される。

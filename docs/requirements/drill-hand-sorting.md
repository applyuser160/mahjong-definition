## 1. 目的・スコープ

### 1.1 目的
現在、何切るドリル（DrillEngine）で生成される手牌（14枚）は、生成ロジックの面子・対子・余剰牌の追加順（または山からのツモ順）のまま格納されており、牌がランダムに並んでいる。  
実戦および一般的な麻雀アプリ・何切る問題集では、手牌は萬子・筒子・索子・字牌の順に整列（理牌: リーパイ）されているのが標準であり、未整列の手牌は視認性・認知負荷を著しく損ねる。  
本機能では、何切る問題生成時に手牌を自動的に昇順整列（理牌）し、CLIおよびWeb UIの両方において視認性の高い手牌表示を提供する。

### 1.2 スコープ

**スコープ内:**
- `Hand` 構造体に手牌（`tiles`）を牌種・数牌番号順にソートするメソッド `sort()` の追加。
- `DrillEngine::generate_problem` における問題生成時の手牌ソート処理の実装。
- Pythonバインディング（`PyDrillProblem` / `py_generate_drill_problem`）におけるソート済み牌列の返却保証。
- CLI（`play_drill.rs`）およびWeb UI（`DrillView.tsx`）での表示確認・整合性検証。
- 単体テストの追加（手牌ソート機能およびドリル問題手牌の整列確認）。

**スコープ外:**
- 実戦対局（`round.rs` 等）における全自動理牌の強制適用（対局進行上の手出し・ツモ切り順序等の保持に影響を与えないよう、本要件は手牌の汎用ソート機能の提供と何切るドリルへの適用に集中する）。

## 2. 用語定義

| 用語 | 定義 |
|------|------|
| **理牌（リーパイ）** | バラバラの手牌を萬子・筒子・索子・字牌の昇順に並べ替えること。 |
| **何切るドリル** | 14枚の手牌と局面（ドラ・巡目）から最善の打牌を選択し、期待値や要因を即座に学習する機能。 |
| **TileName** | 牌の種類を表す列挙型（1m〜9m, 1p〜9p, 1s〜9s, 東南西北, 白發中）。 |

---

## 3. 全体要件

### 3.1 ユーザーニーズ
- 何切るドリルを解く際に、手牌が麻雀の標準的な理牌順（萬子→筒子→索子→字牌、各1〜9）にソートされており、面子や搭子の把握が直感的に行えること。

### 3.2 前提条件・制約
- **前提条件:**
  - `TileName` 列挙型は `Ord`, `PartialOrd` を実装済みであり、萬子(1m-9m)・筒子(1p-9p)・索子(1s-9s)・風牌(東南西北)・三元牌の順序で大小関係が定義されていること。
- **制約:**
  - 手牌（`Hand`）内の牌カウンタ（`counts`）や向聴数計算、打牌候補評価（`evaluate_hand_discards`）の結果に副作用を与えないこと。

## 4. 機能要件

### 4.1 手牌ソート機能（Hand Sort）

#### REQ-001: Hand 構造体のソート機能
**説明:**  
The system shall provide a `sort` method on the `Hand` struct that arranges the active tiles (`tiles[..len]`) in ascending order based on `TileName` ordering.

**受入条件:**
- [x] `hand.sort()` 呼び出し後、`hand.tiles()` の要素が昇順（萬子→筒子→索子→字牌）に整列されていること。
- [x] ソート後も手牌の長さ（`len`）および各牌種カウント（`counts`）が不変であること。

**優先度:** Must  
**備考:** `slice::sort_unstable()` を使用して高速にインプレースソートを行う。

---

### 4.2 何切る問題の手牌整列（Drill Problem Sorting）

#### REQ-002: ドリル問題生成時の手牌自動ソート
**説明:**  
The system shall sort the generated hand tiles before returning a `DrillProblem` in `DrillEngine::generate_problem`.

**受入条件:**
- [x] 生成された `DrillProblem.hand` の牌列が昇順にソートされていること。
- [x] テンパイ問題（`target_shanten: Some(0)`）、一向聴問題（`Some(1)`）、ランダム問題（`None`）のいずれでも手牌が整列されていること。
- [x] 最善打牌（`best_tile`）や打牌候補（`candidates`）の計算結果と整合していること。

**優先度:** Must

---

### 4.3 UI・Pythonバインディング連携

#### REQ-003: Python APIおよびUIでのソート済み表示
**説明:**  
The system shall output the sorted hand tiles in `PyDrillProblem.tiles` and `PyDrillProblem.to_dict()["mpsz"]`.

**受入条件:**
- [x] Python API経由で取得した `drill_problem.to_dict()["mpsz"]` が理牌された順序になっていること。
- [x] Web UI（`DrillView.tsx`）およびCLI（`play_drill.rs`）において、手牌が左から順に理牌順で表示されること。

**優先度:** Must

## 1. 目的・スコープ

### 1.1 目的
麻雀AIおよび分析エンジンにおいて、打牌判断や鳴き判断、期待値（EV）計算の土台となるのが「向聴数（シャンテン数）」および「有効牌・受入枚数（Acceptance）」の計算です。
本要件では、Issue #75 に基づき、手牌に4枚ある牌の仮ツモ除外、可視牌が4枚すべて見えている牌（ヤマゼロ・純カラ）の受入枚数0判定、副露手牌（鳴き手）における向聴数判定・受入計算、および多面張（3面張・5面張・九蓮宝燈等の変則多面待ち）における網羅テストを整備し、エンジンの数理的正確性とロバスト性を保証します。
さらに、将来の探索高速化・モンテカルロ木探索や深層強化学習への組み込みを見据え、受入計算および全打牌受入評価（`analyze_all_discards`）の計算負荷を定量測定するベンチマークスイートを構築します。

### 1.2 スコープ

**スコープ内:**
- **境界値受入計算の仕様明確化と検証**:
  - 手牌にすでに4枚ある牌（暗槓前など）が受入候補から確実に除外されることの検証。
  - 可視牌（`visible_counts`）が4枚見えている牌が、手牌枚数が4枚未満の場合に `waits` に `remaining = 0` として保持され、`total_remaining` には0として計上される仕様の検証。
  - 可視牌が上限値（4枚）を超える入力（異常値・誤入力防衛）に対する飽和計算（`saturating_sub`）の堅牢性検証。
  - 和了形（シャンテン数 -1）に対する受入計算が即座に空結果を返すことの検証。
- **鳴き手（副露手牌）の向聴数・受入計算の検証**:
  - 1副露（手牌10枚）、2副露（手牌7枚）、3副露（手牌4枚）、4副露（手牌1枚：裸単騎）の各段階におけるシャンテン数・受入牌・受入枚数の網羅的検証。
  - 副露牌が可視情報として反映された際の残り枚数減算の正確性検証。
- **複雑な多面張手牌における受入牌・枚数網羅検証**:
  - 3面張（ピアノ線・エントツ・ノベタン等）。
  - 5面張・7面張・9面張（純正九蓮宝燈テンパイ: 9種23枚待ち等）の受入牌種別と残り枚数合計の検証。
  - ヘッドレス一向聴や完全一向聴での有効牌数・枚数の検証。
- **ベンチマークスイート拡充**:
  - `benches/mahjong_benchmark.rs` への向聴数計算（`calculate_shanten`）、受入計算（`calculate_acceptance`）、全打牌候補解析（`analyze_all_discards`）のマイクロベンチマーク追加。

**スコープ外:**
- シャンテン数判定のアルゴリズム自体の全面刷新（インデックス法やビット演算への完全移行等は次期最適化フェーズとし、本フェーズでは現行深さ優先探索の境界値検証と負荷測定を行う）。

## 2. 用語定義

| 用語 | 定義 |
|------|------|
| **向聴数（シャンテン数）** | 和了（アガリ）までに必要な最小手番数（-1: 和了、0: テンパイ、1: 一向聴...）。 |
| **有効牌（受入牌 / Waits）** | 1枚引くことによって手牌のシャンテン数が減少する牌の集合。 |
| **可視牌（Visible Counts）** | 手牌・捨て牌（河）・副露牌・ドラ表示牌など、卓上ですでに公開されている牌の枚数カウント。 |
| **純カラ（ヤマゼロ）** | 待ち牌・受入牌の形としては存在するが、卓上に4枚すべて見えており山に残り0枚の状態。 |
| **副露手牌（鳴き手）** | チー・ポン・カンを行い、手牌が 10枚 / 7枚 / 4枚 / 1枚 に減少した手牌。 |
| **多面張** | 待ち牌が3種類以上存在する複雑な待ち形（3面張、5面張、九蓮宝燈9面張など）。 |

## 3. 全体要件

### 3.1 ユーザーニーズ
- 麻雀エンジンの分析結果（何を切るべきか、何枚受け入れがあるか）が、いかなる極端な盤面（4枚見え、裸単騎、複雑な清一色）でも1枚の狂いなく正確であってほしい。
- 探索アルゴリズムの改善や最適化を行った際に、性能改善とリグレッション（計算速度の劣化）を即座に検知できるようにしたい。

### 3.2 前提条件・制約
- **前提条件**:
  - Rust 2021 エディションでビルド可能であること。
  - 既存の全単体テスト（31件+統合テスト群）および Python バインディングに一切の破壊的変更を生じさせないこと。
- **制約**:
  - `definition/` は完全参照専用であり、一切変更しないこと。

## 4. 機能要件

### 4.1 境界値検証要件

#### REQ-ACC-001: 手牌4枚所持牌のツモ除外
**説明:**  
The system shall exclude any tile that is already held in 4 copies within the hand from the simulated draw in `calculate_acceptance`.

**受入条件:**
- [ ] 手牌に同一牌が4枚ある状態で、その牌が形の上でシャンテン数を進め得る場合であっても、有効牌リスト `waits` に含まれないこと。
- [ ] 単体テストにおいて、手牌に4枚所持している牌が有効牌から除外されるケースが検証されていること。

**優先度:** Must  
**備考:** 例: `1m1m1m1m 2m3m 4p5p6p 7s8s9s` では `1m` は有効牌にならず、`4m` のみが有効牌となる。

---

#### REQ-ACC-002: 可視牌4枚（純カラ）の受入計算
**説明:**  
The system shall calculate the remaining count as 0 for any wait tile whose visible count is equal to or greater than 4, while preserving it in the `waits` list and adding 0 to `total_remaining`.

**受入条件:**
- [ ] 待ち牌が4枚すべて見えている場合、その牌の `remaining` は `0` となること。
- [ ] その牌が `waits` リスト内に存在し、`total_remaining` の加算値が `0` であること。
- [ ] すべての待ち牌が4枚見えている場合、`total_remaining` が `0` となること。
- [ ] 可視牌が5以上入力された場合でも `saturating_sub` によりアンダーフローを起こさず `remaining: 0` となること。

**優先度:** Must  
**備考:** 麻雀ツールとして「形としての待ち（受入）」と「実際の山残り枚数」を明確に分離して表現するため。

---

#### REQ-ACC-003: 和了手牌に対する受入計算の即時終了
**説明:**  
The system shall return empty waits and total remaining 0 immediately when `calculate_acceptance` is invoked on a winning hand (shanten < 0).

**受入条件:**
- [ ] 和了形の手牌を入力した際、`waits` が空で `total_remaining` が 0、`current_shanten` が -1 である結果が返ること。

**優先度:** Must  

---

### 4.2 副露手牌（鳴き手）要件

#### REQ-ACC-004: 副露手牌における受入牌・枚数判定
**説明:**  
The system shall accurately calculate shanten and acceptance for hands with open melds (1 to 4 melds, corresponding to 10, 7, 4, and 1 remaining concealed tiles).

**受入条件:**
- [ ] 1副露（手牌10枚）の両面待ち・辺張待ち・嵌張待ち・シャンポン待ちが正しく判定されること。
- [ ] 2副露（手牌7枚）および 3副露（手牌4枚）でのシャンテン数と受入枚数が正しく算出されること。
- [ ] 4副露（手牌1枚：裸単騎）において、単騎待ち牌が受入牌として正確に判定され、残り枚数が手牌1枚を除いた3枚（他に見えていなければ）と算出されること。
- [ ] 副露した牌が `visible_counts` に含まれた場合、受入枚数が正しく減算されること。

**優先度:** Must  

---

### 4.3 多面張・網羅検証要件

#### REQ-ACC-005: 多面張パターンの受入判定
**説明:**  
The system shall accurately identify all wait tiles and their exact remaining counts for complex multi-sided wait patterns.

**受入条件:**
- [ ] 3面張（例: `23456m` の 1-4-7m 待ち）で3種12枚が正確に判定されること。
- [ ] 5面張（例: `2345556m` 等の複合形）で5種すべての有効牌が判定されること。
- [ ] 純正九蓮宝燈テンパイ（`1112345678999m`）において、1m〜9mの全9種・合計23枚が漏れなく受入牌として判定されること。
- [ ] 完全一向聴（両面×2＋対子＋刻子/順子）およびヘッドレス一向聴において、有効牌種別と合計枚数が正確に算出されること。

**優先度:** Must  

---

### 4.4 ベンチマーク要件

#### REQ-ACC-006: 性能測定ベンチマークスイート
**説明:**  
The system shall provide Criterion benchmark functions measuring the performance of `calculate_shanten`, `calculate_acceptance`, and `analyze_all_discards`.

**受入条件:**
- [ ] `benches/mahjong_benchmark.rs` に `calculate_shanten`（通常手、清一色、七対子、国士無双）のベンチマークが追加されていること。
- [ ] `calculate_acceptance`（テンパイ、一向聴、多面張、副露手牌）のベンチマークが追加されていること。
- [ ] `analyze_all_discards`（14枚手牌からの14通り全打牌評価）のベンチマークが追加されていること。
- [ ] `cargo bench --bench mahjong_benchmark -- --test`（スモークテスト）が正常終了すること。

**優先度:** Must

## 1. 目的・スコープ

### 1.1 目的
現在、麻雀AIエンジン（`rust-mahjong`）の打牌評価API（`evaluate_hand_discards` 等）およびUIバックエンド（`match_manager.py`）の打牌検討処理において、巡目（6巡目固定）、山残り（50枚固定）、自風・場風（東固定）、および河の見えている牌（可視牌情報が空）などの局面情報がハードコードまたは省略されています。  
本改修の目的は、**実際の対局状態（巡目、山残り枚数、自風・場風、ドラ表示牌、河および副露の可視牌）をエンジンへ動的かつ完全に連携**させることで、終局レビューにおける悪手判定およびリアルタイムAI HUDの評価精度を大幅に向上させることです。

### 1.2 スコープ

**スコープ内:**
- **Python API（`mahjong` リポジトリ）の拡張**:
  - `py_evaluate_hand_discards` および `py_evaluate_placement_discards` において、対局コンテキスト（巡目、山残数、自風、場風、ドラ表示牌、可視牌リスト）をオプショナル引数として受け取れるよう拡張。
  - 引数が省略された場合は従来のデフォルト値を適用し、完全な後方互換性を維持。
  - Python型定義（`_core.pyi`）および `__init__.py` のラッパー更新。
- **UIバックエンド（`mahjong-ui` リポジトリ）のコンテキスト連携**:
  - `MatchManager` に自風算出メソッド（座順と親番から算出）および場に見えている全牌（手牌、各家の河、各家の副露面子、ドラ表示牌）の集約メソッドを実装。
  - `user_discard` 内の打牌候補評価（レビュー記録用）において、上記コンテキストを渡して呼び出すよう改修。
  - `get_hud_data` 内のリアルタイムAI HUD生成においても、同様に対局コンテキストを連携。

**スコープ外:**
- 和了確率や危険度モデル自体の数理アルゴリズム刷新（Issue #76〜#79 の別タスク）。
- フロントエンド（React）のUIコンポーネント構造の変更。

## 2. 用語定義

| 用語 | 定義 |
|------|------|
| `AnalysisContext` | Rustコアエンジン内で打牌評価（EV・和了確率・打点）を行う局所状況構造体（巡目、山残り、自風、場風、ドラ等）。 |
| 可視牌 (`visible_tiles`) | 対局者から現在見えているすべての牌（自身の手牌、各プレイヤーの河、副露牌、ドラ表示牌）。残り牌数算出の基礎となる。 |
| `MatchManager` | `mahjong-ui/backend/match_manager.py` 内で4人戦のゲーム進行とレビュー記録を統括するクラス。 |

## 3. 全体要件

### 3.1 ユーザーニーズ
- 実際の対局で、序盤・終盤の巡目や残り山枚数、自風・場風（役牌条件）、河に見えている牌の枚数（壁・ノーチャンス、待ちの残り枚数）に応じた正確な推奨手・EV損失を知りたい。
- 固定パラメータによる不正確な「悪手判定」を解消したい。

### 3.2 前提条件・制約
- **後方互換性の維持**: 既存のテストスクリプトや旧シグネチャによる呼び出しが一切破損しないこと。
- **低レイテンシ**: 毎打牌時の可視牌集計およびAPI連携がミリ秒未満で完了すること。

## 4. 機能要件

### 4.1 Python API (`mahjong` リポジトリ: Issue #80)

#### REQ-API-001: 打牌評価APIの動的コンテキスト受取
**説明:**  
The system shall `py_evaluate_hand_discards` において、手牌・親フラグ・ドラ表示牌に加え、巡目（`turn_number`）、残り山枚数（`remaining_wall_tiles`）、自風（`seat_wind`）、場風（`round_wind`）、可視牌リスト（`visible_tiles`）をオプション引数として受け取ること。

**受入条件:**
- [ ] 引数省略時は、従来通りのデフォルト値（6巡目、50枚、東風、可視牌=手牌のみ）で動作すること。
- [ ] 引数指定時は、指定された値が Rust 側の `AnalysisContext` および `visible_counts` に正しく反映されて打牌評価が行われること。

#### REQ-API-002: 順位EV・AI HUD API の動的コンテキスト受取
**説明:**  
The system shall `py_evaluate_placement_discards` および `py_get_ai_hud_data` においても、同様に対局コンテキスト（巡目、山残数、自風、可視牌リスト）を受け取って評価に反映すること。

**受入条件:**
- [ ] `MatchContext` に加えて上記コンテキストを受け取れること。

---

### 4.2 UIバックエンド (`mahjong-ui` リポジトリ: Issue #1)

#### REQ-UI-001: 自風計算および可視牌集約
**説明:**  
The system shall `MatchManager` において、以下の状態取得ヘルパーを提供すること：
1. `get_seat_wind(player_idx: int) -> TileName`: 親番インデックスとプレイヤーインデックスから自風（東・南・西・北）を正確に算出する。
2. `get_visible_tiles(player_idx: int) -> List[TileName]`: 指定プレイヤーの手牌、全4名の河（捨て牌）、全4名の副露面子牌、および現在のドラ表示牌を網羅したリストを生成する。

**受入条件:**
- [ ] 親番が変わった場合でも、自風が麻雀の正規順（親が東、下家が南、対面が西、上家が北）で算出されること。
- [ ] 手牌・河・鳴き牌・ドラ表示牌の全枚数が重複なく正しく可視牌リストに含まれること。

#### REQ-UI-002: 打牌検討時の完全コンテキスト連携
**説明:**  
The system shall `user_discard` におけるレビュー記録処理（`record_decision`）の直前で、REQ-UI-001 により収集した対局コンテキストを付与して `evaluate_hand_discards` を呼び出すこと。

**受入条件:**
- [ ] 実際の巡目（`turn_count + 1`）、山残数（`len(self.wall)`）、自風、場風、ドラ、可視牌が渡されること。
- [ ] 例外発生時もゲーム進行が停止しないよう安全なフォールバック処理を維持すること。

## 5. 非機能要件

### 5.1 性能要件
- 可視牌リストの生成およびAPI呼び出しにかかる処理時間は、1打牌あたり 1ms 以下であること。

### 5.2 保守性・品質要件
- 単体テスト（Rust 側および Python 側）によって、パラメータ渡し時と省略時の挙動の一貫性が検証されていること。

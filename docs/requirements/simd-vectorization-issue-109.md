## 1. 目的・スコープ

### 1.1 目的

麻雀の牌カウント配列（`counts: [u8; 35]`）は、インデックス 1〜34 の 34 要素で各牌の枚数（0〜4枚）を 1 バイト値として保持しています。
この配列構造は x86_64 の AVX2 レジスタ（256bit = 32 バイト）と親和性が極めて高いメモリ表現です。

現在、以下のホットパスにおいてスカラー処理と条件分岐が用いられています：
1. **七対子シャンテン数計算 (`calculate_chitoitsu_shanten`)**:
   - `counts[1..=34]` の 34 要素をスカラー走査し、`c >= 2`（対子数）と `c >= 1`（種類数）を分岐を伴うループで集計。
   - 何切る解析やモンテカルロ木探索等で数百万〜数千万回実行されるホットパス。
2. **スーツキーのエンコード (`encode_suit_key`)**:
   - 各数牌スーツの 9 牌について、重み $5^k$（$k=0..8$）を逐次ループで乗算・累積。

本改修の目的は：
- x86_64 AVX2 命令セットを活用し、アンアラインドロード（`_mm256_loadu_si256`）と並列比較・マスク変換・POPCNT（`_mm256_movemask_epi8` / `count_ones`）による **ブランチレス・並列七対子判定** を実現すること。
- スーツキー計算において Base-5 重み特性に応じた分割並列内積を導入し、逐次乗算ループを高速化すること。
- 非 AVX2 環境（ARM、古い x86_64 等）やターゲット機能非対応環境でも完全に動作するスカラーフォールバックおよび実行時 feature detection（`is_x86_feature_detected!("avx2")`）を担保すること。
- 既存の判定結果・キー算出結果との完全な同値性を検証すること。

### 1.2 スコープ

**スコープ内:**
- `shanten.rs`: AVX2 対応の高速七対子計算関数 `calculate_chitoitsu_shanten_avx2` の実装とスカラー版とのディスパッチ
- `suit_table.rs`: AVX2 / SIMD を用いたスーツキー算出 `encode_suit_key_simd` の実装とスカラー版とのディスパッチ
- 境界条件・非アラインメントへの安全な配慮（`loadu` の採用、34 要素のうち 32 要素一括 + 末尾 2 要素スカラー処理）
- Base-5 符号付き 16bit 整数オーバーフロー対策（$5^7, 5^8$ を考慮した桁分割設計）
- 非 AVX2 環境用スカラーフォールバックと実行時/コンパイル時切り替え
- プロパティテスト・単体テスト（全有効スーツキー、ランダム合法手牌、境界ケース）
- Criterion ベンチマークによるスループット測定・比較

**スコープ外:**
- 国士無双判定のベクトル化（13要素と疎であり、テーブルルックアップやビット演算で十分高速なため）
- データ構造全体の 32 バイトアライメント強制変更（既存 API 破壊の回避）

## 2. 機能要件 (FR)

### FR-1: 七対子判定の AVX2 ベクトル化
- `counts[1..=32]` の 32 要素を `_mm256_loadu_si256` で 256bit レジスタに一括ロードすること。
- `_mm256_cmpgt_epi8` により、各牌が 0 より大（種類数）、1 より大（対子数）のバイトマスクを一括生成すること。
- `_mm256_movemask_epi8` と `count_ones()`（POPCNT 命令）により、分岐なしで 32 牌中の対子数と種類数を集計すること。
- 残り 2 要素（`counts[33]`, `counts[34]`）をスカラー処理して合算すること。

### FR-2: スーツキー算出（Base-5 内積）のベクトル化
- 9 牌の枚数に対し、重み $5^k$ を乗算する処理において、`i16` の表現範囲（$\le 32,767$）に収まるよう桁分割（低位 4 桁 $5^0..5^3$ と高位 5 桁 $5^0..5^4 \times 5^4$、または 8 桁 + 1 桁）を行い、SIMD 積和演算を安全に適用すること。

### FR-3: ポータビリティとフォールバック
- `cfg(all(target_arch = "x86_64", target_feature = "avx2"))` または実行時チェック `is_x86_feature_detected!("avx2")` を備え、非対応環境では自動的に従来のスカラー実装を呼び出すこと。

## 3. 非機能要件 (NFR)

### NFR-1: 計算結果の完全一致
- 任意の合法手牌、および数牌の全有効パターンにおいて、AVX2 実装とスカラー実装の戻り値が 100% 一致すること。

### NFR-2: メモリアクセス安全性
- アライメント違反による SIGBUS / General Protection Fault や、配列外読み込み（OOB read）を一切発生させないこと。

### NFR-3: パフォーマンス向上
- Criterion ベンチマークにおいて、七対子シャンテン数計算のスループット向上を確認すること。

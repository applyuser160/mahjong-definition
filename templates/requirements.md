## 5. 要件品質チェックリスト

### 5.1 個々の要件の品質（5特性）

各要件に対して以下をチェックする。

| REQ番号 | 必要性 | 明白性 | 単一性 | 検証性 | 正確性 |
|---------|--------|--------|--------|--------|--------|
| REQ-001 | ☐ | ☐ | ☐ | ☐ | ☐ |
| REQ-002 | ☐ | ☐ | ☐ | ☐ | ☐ |

- **必要性（Necessary）:** この要件がなければシステムが成立しないか
- **明白性（Unambiguous）:** 曖昧な解釈が生じないか
- **単一性（Singular）:** 1つの要件で複数の事柄を述べていないか
- **検証性（Verifiable）:** テストや観測で確認可能か
- **正確性（Correct）:** 実際のニーズを正確に反映しているか

## 6. 曖昧語禁止リスト

以下の語は要件に使用しないこと（曖昧性を生むため）。

| 禁止語 | 言い換え例 |
|--------|-----------|
| best / most | 具体的な数値・指標を使う（例: "95%以上の精度で"） |
| user friendly / easy to use | 具体的な操作手順・完了時間を定義する |
| it / this / that | 指示語を避け、対象名詞を明記する |
| almost always / generally | 具体的な割合・頻度で記述する（例: "99%以上の場合"） |
| provide support for | "〜を実行できる" など動詞で具体化する |
| if possible | 要件として必要なら `shall`、不要なら削除する |
| flex / scalable | 具体的な拡張条件・数値を記述する |
| and/or | 複数要件に分割する |
| etc. | 網羅的に列挙する |
